# Human Design Fishbone

## Purpose

This is the Human Design-specific content roadmap. It provides a central spine and expandable branches so the vault can grow coherently without requiring every topic to be completed at once.

The fishbone is both:

- a learning map for people;
- a content backlog for the repository;
- a boundary map showing where Human Design interfaces with adjacent domains.

## Growth sequence

Build the fishbone in vertical slices rather than filling one branch in isolation.

### Slice 1: decision mechanics

Complete the path:

```text
Type → Strategy → Authority → Signature → Not-Self Theme
```

This is the most approachable and immediately usable slice. The current notes already provide a foundation.

### Slice 2: BodyGraph structure

Create the nine Center notes, then explain how Channels, Definition, and split types connect them.

### Slice 3: chart mechanics

Expand planetary elements, Design and Personality, Gates, Lines, and Activations. Keep astrology and astronomy as clearly bounded interfaces.

### Slice 4: archetypal synthesis

Add Profiles, Incarnation Crosses, Circuitry, and representative Channels before attempting all 64 Gates and 36 Channels.

### Slice 5: application

Develop reading methodology, contemplative exercises, and carefully scoped case studies. Keep personal charts separate from the theory layer.

## Branch contract

Every new branch should answer four questions:

1. What does this concept mean inside Human Design?
2. How does it relate to the spine and neighboring branches?
3. What adjacent domain does it touch, if any?
4. What belongs outside this repository?

Use the [Human Design page specification](human-design-spec.md) for note structure and the [Human Design boundaries](human-design-boundaries.md) for scope decisions.

## Completion is not the goal

The fishbone is intentionally open-ended. A branch is useful when it provides a reliable conceptual foundation for further work, not only when every possible page has been written.
